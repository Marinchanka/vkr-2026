# ЛР 2 — обоснование актуальности ВКР

**Тема ВКР:** Разработка подсистемы интеграции и семантической нормализации разнородных товарных каталогов для интеллектуального онлайн-консультанта
**Автор:** Марина Машковцева
**Формат работы:** индивидуальная ВКР в рамках командного проекта «Интеллектуальный онлайн-консультант».
**Зона ответственности:** загрузка товарных каталогов, анализ структуры, сопоставление и нормализация характеристик, подготовка данных к поиску. Диалоговый интерфейс разрабатывается в других частях проекта.

## 2. Обзор литературы

В контексте работы следует различать три задачи. **Schema matching** устанавливает соответствие между полями источника и внутренней моделью (`product_name → title`, `cost → price`). **Нормализация значений** приводит разные формы одной характеристики к общему виду (`43 inch → screen_size_inch = 43`). **Entity/product matching** определяет, относятся ли две записи к одному физическому товару. Сопоставление товарных записей может дополнять интеграцию каталогов, но не заменяет установление соответствий между их полями. После интеграции данные также необходимо подготовить к поиску по естественному запросу.

### Выводы по обзору

Литература показывает, что задача сопоставления неоднородных схем давно изучается, однако выбор метода остаётся зависимым от структуры данных, наличия примеров значений и допустимых затрат [1–3]. Правила и словари удобны для очевидных соответствий (`price → price`), но хуже переносятся на новые формулировки. Embeddings позволяют учитывать сходство по смыслу [4], однако близость названий не гарантирует совпадения назначения поля: `volume` может означать объём упаковки либо объём памяти. В работах с LLM рассматривается использование контекста и confidence scoring [5–6], но результаты чувствительны к постановке запроса и проверялись на других предметных областях.

Из этого следует рабочая гипотеза: **каскад, в котором сначала применяются дешёвые и объяснимые правила, затем семантическая модель, а LLM или ручная проверка подключаются для неоднозначных случаев, может уменьшить стоимость подключения нового каталога по сравнению с использованием LLM для каждого поля без существенного снижения качества**. Для проверки гипотезы потребуются сопоставимые тестовые каталоги, эталонные соответствия и учёт количества ручных исправлений.

Отдельная задача — проверить, сохраняется ли полезность нормализованных данных для поиска. Высокая точность сопоставления полей не означает автоматически хорошую релевантность найденных товаров: после сопоставления полей могут остаться ошибки в единицах измерения, категориях и извлечении характеристик из описаний.

## 3. Обзор и сравнение аналогов

Для сравнения выбраны инструменты, решающие отдельные задачи интеграции каталогов: сопоставление схем, очистку и нормализацию данных, сопоставление записей.

### Прямые аналоги

**COMA.** Подход комбинирует несколько алгоритмов сопоставления схем по названиям, структуре и, в отдельных конфигурациях, значениям. Это прямой аналог модуля mapping. Ограничение для нашей постановки: сопоставление схем само по себе не решает нормализацию физических величин и подготовку товарных описаний к поиску. [Описание метода](https://doi.org/10.1016/B978-155860869-6/50060-3), [реализация в Valentine](https://github.com/delftdata/valentine/blob/master/docs/matchers.md).

**Valentine.** Открытый Python-инструмент для запуска и оценки алгоритмов schema matching. Он полезен для сравнения baseline, но не является готовым адаптером интернет-магазина с импортом, сохранением правил и созданием поискового индекса. [GitHub](https://github.com/delftdata/valentine), [статья](https://doi.org/10.1109/ICDE51399.2021.00047).

**Matchmaker.** Исследовательский подход к автоматическому сопоставлению схем посредством LLM с генерацией кандидатов, уточнением и оценкой уверенности. Ближе к предполагаемому интеллектуальному этапу нашей подсистемы. Ограничение: опубликованная оценка относится прежде всего к медицинским схемам; поведение на неоднородных товарных каталогах следует проверять отдельно. [Публикация](https://proceedings.mlr.press/v267/seedat25a.html).

### Косвенные аналоги

**OpenRefine.** Позволяет очищать значения, находить похожие записи и выполнять reconciliation с внешними сервисами. Полезен как пример полуавтоматической обработки с участием человека. Но, согласно документации, синтаксическая кластеризация не заменяет семантическое сопоставление и обычно требует просмотра предложенных соответствий. [Документация](https://openrefine.org/docs/manual/reconciling), [ограничения кластеризации](https://openrefine.org/docs/technical-reference/clustering-in-depth).

**Ditto.** Сопоставляет записи, которые могут описывать один объект, с помощью предобученных языковых моделей. Может пригодиться, если в дальнейшем появится задача дедупликации товаров между источниками. Однако сопоставление товаров не тождественно определению значения полей нового каталога. [Статья](https://doi.org/10.14778/3421424.3421431), [код](https://github.com/megagonlabs/ditto).

### Выводы по сравнению

Для базового сравнения целесообразно использовать идеи COMA и инструменты Valentine: они позволяют измерить, насколько далеко можно продвинуться без LLM. Из Matchmaker интересны разделение на генерацию кандидатов, уточнение и оценку уверенности. Из OpenRefine — механизм подтверждения спорных преобразований человеком и сохранения принятых решений.

Планируемая подсистема объединит отдельные этапы в **единый процесс обработки товарного каталога**: загрузить неизвестный источник, определить и нормализовать поля, запросить уточнение только при необходимости, сохранить соответствия и подготовить данные к поиску. Эффективность такого процесса будет оценена по качеству сопоставления, трудозатратам и стоимости обработки.

## 4. Итоги

**Итоговая тема ВКР:** Разработка подсистемы интеграции и семантической нормализации разнородных товарных каталогов для интеллектуального онлайн-консультанта.

**УДК для тезиса:** **004.62** (обработка данных).

**Ключевые слова:** интеграция данных, разнородные товарные каталоги, сопоставление схем, семантическая нормализация, schema matching, embeddings, большие языковые модели, гибридный подход, поиск товаров.

### Актуальность исследования

При подключении нового интернет-магазина консультант сталкивается не только с разными форматами передачи каталога, но и с разной семантикой полей. Одна и та же характеристика может называться по-разному, иметь разный тип или единицу измерения; короткие названия вроде `size` без категории и примеров значений неоднозначны. Поэтому простая загрузка JSON или CSV ещё не делает ассортимент пригодным для интеллектуального поиска.

Необходимость автоматизации сопоставления схем рассматривается в исследованиях не менее двух десятилетий [1–3], но появление embeddings и LLM расширило набор доступных методов [4–6]. При этом более сложный метод не обязательно экономически оправдан для каждого поля. Для подключения нового магазина важна не только точность, но и время интеграции, число действий оператора и затраты на обращения к моделям. Аналоги решают отдельные части этой задачи, однако не закрывают весь рассматриваемый сценарий с повторным использованием настроек и подготовкой каталога к поиску.

ВКР направлена на проверку практического компромисса: **можно ли добиться качества автоматической адаптации, близкого к LLM-подходу, вызывая дорогой метод только для сложных соответствий**. Дополнительная проверка качества поиска нужна, чтобы оценивать не формальную правильность mapping, а пользу нормализованного каталога для конечного сервиса.

### Цель исследования

Разработать и экспериментально оценить подсистему автоматизированной адаптации разнородных товарных каталогов к единой модели интеллектуального онлайн-консультанта, исследовав соотношение качества семантического сопоставления, объёма ручной настройки и затрат при использовании правил, embedding-моделей, LLM и гибридного подхода.

### Задачи исследования

1. Проанализировать существующие методы schema matching, семантической нормализации и подготовки товарных данных к поиску.
2. Определить внутреннюю модель товара и требования к данным для выбранной товарной области.
3. Подготовить не менее трёх каталогов, различающихся структурой и способом получения (например, API/JSON, XML/YML и CSV), а также эталонные соответствия полей.
4. Реализовать загрузку и первичный анализ структуры, типов и примеров значений полей.
5. Реализовать сопоставление и нормализацию на основе правил, а также альтернативные семантические способы обработки неоднозначных характеристик.
6. Разработать и проверить гибридный механизм выбора способа сопоставления с возможностью ручного подтверждения и сохранения правил.
7. Подготовить нормализованные записи к поиску и реализовать интерфейс получения подходящих товаров.
8. Сравнить подходы по Precision/Recall/F1 для mapping, доле автоматически обработанных полей, числу ручных исправлений, времени и вычислительным/API-затратам; дополнительно оценить качество выдачи по выбранным поисковым метрикам.

Для исследовательской части предполагается использовать **одну выбранную товарную область** (например, электронику или освещение), а не заявлять универсальную обработку любых товаров. **Предполагаемый результат:** сервис для подключения ранее неизвестных товарных каталогов в поддерживаемых форматах без разработки отдельного адаптера под каждый магазин, а также экспериментальная оценка методов сопоставления и нормализации данных.
